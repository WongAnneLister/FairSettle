## Design decisions (fixed, do not change)

- Package `com.paymentsledger.provider.adapter.paypal`. JDK `java.net.http.HttpClient` and the Jackson `ObjectMapper` already on the classpath; **no new Maven dependency**.
- The only allowed base URL is `https://api-m.sandbox.paypal.com`, compared exactly after removing one trailing `/`. A null or blank value means the sandbox (the repo's `.env` has `PAYPAL_BASE_URL=` empty). Anything else, including other ports, paths, user info, `http`, or a longer host, is refused when the client is constructed, so a Spring bean fails and startup fails.
- The token is cached in memory, never persisted, never logged. Refresh time = time the token request was sent + `expires_in` − margin, with margin = min(300 s, `expires_in` / 2). The token is reused while `now < refreshAt`.
- Token fetches are serialized (`synchronized`), so concurrent callers trigger one token request.
- A 401 from a target call makes the client drop the token it used (only if it is still the cached one), fetch a new token and resend the **identical** request (same method, path, headers including `PayPal-Request-Id`, body) exactly once. No other status is retried.
- The client returns what happened in a sealed result type and does not classify it into `ProviderCallClassification`. Classification belongs to the adapters (F05+). The result keeps the distinction that matters for UNKNOWN handling: the target request was never sent (`NotSent`), or it may have been sent and no answer came back (`NoResponse`).
- Redirects are never followed (`HttpClient.Redirect.NEVER`): a 3xx is returned as a response.
- The client is the only code that sets `Authorization`; a caller-supplied `Authorization` header is refused.
- F04 adds no logging anywhere in this package.

```java
public sealed interface PayPalExchange {
    /** PayPal answered the target request. authRetried: the answer came from the single retry after a 401. */
    record Responded(int status, String body, String debugId, boolean authRetried) implements PayPalExchange {}
    /** The target request was not sent because no token could be obtained. No remote effect. */
```

### `PayPalAuthClient.java` (new)

```java
public final class PayPalAuthClient {
    public static final String SANDBOX_BASE_URL = "https://api-m.sandbox.paypal.com";
    static final Duration MAX_REFRESH_MARGIN = Duration.ofMinutes(5);
    static final String TOKEN_REJECTED = "TOKEN_REJECTED";
    static final String TOKEN_UNAVAILABLE = "TOKEN_UNAVAILABLE";
    static final String TOKEN_CONTRACT_MISMATCH = "TOKEN_CONTRACT_MISMATCH";
    static final String NO_RESPONSE = "NO_RESPONSE";
    static final String INTERRUPTED = "INTERRUPTED";

    public PayPalAuthClient(String baseUrl, String clientId, String clientSecret, Clock clock)
    // Only tests inject a transport; production always uses JdkPayPalTransport.
    PayPalAuthClient(String baseUrl, String clientId, String clientSecret, Clock clock, PayPalTransport transport)

    public PayPalExchange exchange(PayPalHttpRequest request)
    static String sandboxBaseUrl(String configured)
    @Override public String toString()   // "PayPalAuthClient[" + SANDBOX_BASE_URL + "]", nothing else
}
```

Private state: `final URI base`, `final String basicAuth` (precomputed `"Basic " + Base64(clientId + ":" + clientSecret, UTF-8)`), `final Clock clock`, `final PayPalTransport transport`, `private record CachedToken(String value, Instant refreshAt)`, `private CachedToken token` (guarded by `this`).

**Constructor:**

- `sandboxBaseUrl(baseUrl)`: null or blank → `SANDBOX_BASE_URL`; else strip one trailing `/`; if not equal to `SANDBOX_BASE_URL` → `IllegalArgumentException("PayPal base URL must be the sandbox " + SANDBOX_BASE_URL)`. The message never echoes the configured value.
- `clientId` or `clientSecret` null or blank → `IllegalArgumentException("PayPal sandbox client id and secret are required")`.
- `clock`, `transport` non-null (`Objects.requireNonNull`).
- No network call.

**`exchange(request)`, in order:**

1. Transaction guard, same condition and message style as `StripeGateway.guard`: `IllegalStateException("PayPal calls must execute outside local transactions and business locks")`.
2. Validate, else `IllegalArgumentException` with a fixed message (no request content echoed). Nothing is sent when validation fails.
   - `method` is one of `GET`, `POST`, `PATCH`.
   - `path` starts with `/`, does not start with `//`, and contains none of `://`, `@`, `\`, whitespace, or control characters.
   - No header named `Authorization` (case-insensitive).
3. `CachedToken t = token()`. If it fails, return `NotSent(reason)`.
4. `send(request, t.value)`, which builds headers in this order: the caller's headers, then `Authorization: Bearer <token>`, `Accept: application/json`, and `Content-Type: application/json` when `body != null` and the caller set no `Content-Type`. URI = `base + path`.
   - `IOException` (includes `HttpTimeoutException`) → `NoResponse(NO_RESPONSE)`.
   - `InterruptedException` → `Thread.currentThread().interrupt()`, `NoResponse(INTERRUPTED)`.
5. If status is 401:
   - `invalidate(t.value)`: clear the cache only if it still holds this value.
   - `token()` again. If that fails, return the **first** response as `Responded(401, body, debugId, false)`.
   - Otherwise send the identical request once with the new token; map exceptions as in step 4. The response becomes `Responded(status, body, debugId, true)`.
6. Otherwise return `Responded(status, body, debugId, false)`.

**`token()` (private, `synchronized`):**

- If `token != null && clock.instant().isBefore(token.refreshAt)`, return it.
- Else `Instant sentAt = clock.instant()`, then `POST base + "/v1/oauth2/token"` with headers `Authorization: <basicAuth>`, `Content-Type: application/x-www-form-urlencoded`, `Accept: application/json` and body `grant_type=client_credentials`.
- Outcomes (nothing is cached on failure):
  - `IOException` → `TOKEN_UNAVAILABLE`. `InterruptedException` → re-interrupt, then `TOKEN_UNAVAILABLE`.
  - Status 400 or 401 → `TOKEN_REJECTED`.
  - Any other non-200 → `TOKEN_UNAVAILABLE`.
  - 200 but the body is not a JSON object, or `access_token` is missing/blank/not a string, or `token_type` is not `Bearer` (case-insensitive), or `expires_in` is not an integer ≥ 1 → `TOKEN_CONTRACT_MISMATCH`.
  - Otherwise cache `new CachedToken(access_token, sentAt + expires_in − min(MAX_REFRESH_MARGIN, expires_in/2))` and return it.
- Implement failures with a private unchecked `TokenFailure(String reason)` exception (no message text, `writableStackTrace=false`) caught in `exchange`. Do not use a public exception type.

## Risks

- **PayPal returns `expires_in` around 32400 s.** Hard-coding that would break if PayPal shortens it. The margin rule (min 5 min, half the lifetime) handles any positive value, and tests 3 and 4 pin both branches.
- **A 401 retry could duplicate a write.** 401 means PayPal rejected authentication before processing. The retry reuses the same `PayPal-Request-Id`, so even a mistaken 401 replays the original result instead of creating a second capture or refund (ADR D6). Test 5 asserts the identical request.
- **The token could be refreshed while another thread still uses the old one.** `invalidate` clears only the token that got the 401, so a fresher token fetched by another thread is not thrown away.
- **The token or secret could leak.** No logging. Messages are fixed strings and `toString` is fixed. Test 21 guards this.
- **A misconfigured base URL could send credentials elsewhere.** Exact match, no redirects followed, relative-path validation (tests 17, 19).
- **Windows line endings.** Spotless runs before each commit (`./mvnw spotless:apply`).

## Deviations

Filled in during review: what changed from this plan, why, and in which commit.

- Before implementation, Codex found that tests 3 and 4 queued `tok-2` before the second target reply, although the second exchange reuses the cached `tok-1`. Queues corrected to `token tok-1, 200, 200, token tok-2, 200`. Tests 15 and 16 now say a new transport and client per case, and the helpers note that replies are consumed strictly in call order.
- Review (commits 34329fd, 2e251cb): no code changed in review. Differences from the plan, all stricter than the plan and none weakening it:
  - `send()` drops any caller `Accept` header (case-insensitive) before setting `Accept: application/json`, so exactly one `Accept` is sent. The `Content-Type` check is also case-insensitive.
  - `validate()` additionally refuses a null request, Unicode space characters (`Character.isSpaceChar`), and any path for which `URI.create(base + path)` fails, all with fixed messages.
  - `token()` also maps `DateTimeException`/`ArithmeticException` (an `expires_in` too large to add to the clock) to `TOKEN_CONTRACT_MISMATCH`, and clears an expired cached token before fetching a new one.
  - Test 12 has three extra bodies (`access_token` a number, `access_token` blank with spaces, `expires_in` 1.5). Test 19 has three extra paths (`/v2/https://evil.example`, a tab, a control character). Tests were not edited after commit 34329fd.
